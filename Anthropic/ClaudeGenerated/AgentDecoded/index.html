    What they all share

    These ideas have converged across the field. If you learn them once, they carry over to any framework.

    A reason–act–observe loop

    Under the hood each one calls the model, runs any tool calls it requests, feeds the results back, and repeats until a stop condition.

    Tools are typed functions

    You write a normal function; the framework turns its signature and docstring into a JSON schema the model can call.

    State that outlives one call

    Conversation history, scratch state and sessions persist between turns, so a run can pause, resume or be inspected.

    Agents compose into teams

    One agent can call, hand off to, or supervise others. The shape of that team is where frameworks differ most.

    MCP for outside tools

    All eight can load tools from Model Context Protocol servers, so one integration works across frameworks.

    Traces you can inspect

    Every step, tool call and token count is recorded, usually exportable to OpenTelemetry or a hosted tracing UI.
