Inside a language model, almost everything is a matrix

Your prompt becomes lists of numbers, and those numbers pass through layers of matrix multiplication. A handful of ideas from linear algebra do most of the work. Each one below is something you can move.

Words become points in space

A model can't read letters. It first swaps each token for a vector: a list of hundreds or thousands of numbers. Tokens with related meanings end up pointing in similar directions, so geometry carries meaning.

Here the space has two dimensions so you can see it. Drag the amber point. The list ranks words by cosine similarity, the cosine of the angle between two vectors. A value of 1 means they point the same way.

Directions mean things too. The step from man to king is nearly the same step as woman to queen, so vector arithmetic can follow an analogy.

A layer is a matrix that moves every point

Each layer of a neural network multiplies its input vector by a weight matrix. In two dimensions you can watch that happen. The blue grid is the plane after the matrix has pushed it around.

The two arrows show where the axes land, and they are the matrix's columns: the pink arrow is the left column, the teal arrow is the right column. Change a number and the whole plane follows. Real models do the same in thousands of dimensions, with matrices learned from data.

Attention is a table of dot products

To update a token, the model asks which other tokens matter for it. Every token carries a query (what it is looking for) and a key (what it offers). The dot product of a query and a key scores the match. Softmax then turns the scores into weights that add up to 1, and the token's new vector is a weighted blend of the others.

Scale is a matrix multiplication budget

Nearly all of a model's parameters sit in weight matrices, and nearly all of its compute is multiplying vectors by them. Change the width and the number of layers to see how the totals grow.

Width counts twice. A weight matrix is d × d, so doubling d quadruples the entries. This is also why GPUs matter: they are built to multiply large matrices in parallel.

Rough estimate: each transformer layer holds about 12·d² numbers (4·d² in attention, 8·d² in the feed-forward block). Real models differ in the details and also store embeddings.

Big matrices are often secretly small

A matrix of size n × n can be rebuilt from a few "rank 1" pieces, each one a column times a row. Keep the strongest r pieces and you store about r × 2n numbers instead of n². The singular value decomposition finds the best pieces.

Slide the rank and watch a 32 × 32 picture come back into focus. Low-rank updates are also the idea behind LoRA, a way to fine-tune a model by training two thin matrices instead of one huge one.

The same few operations, repeated

Embeddings
Vectors. Meaning becomes direction and distance, and similarity is a cosine.
Layers
Matrix–vector products. Each layer re-mixes every feature into new ones, and a bend between layers keeps the stack from collapsing into a single matrix.
Attention
Dot products between queries and keys, a softmax, then a weighted sum of value vectors.
Training and serving
Large matrix–matrix multiplications that GPUs run in parallel. Parameter counts and compute follow directly from matrix sizes.
Efficient fine-tuning
Low-rank factorization: approximate or update a big matrix with two thin ones.

These demos are simplified. They use two dimensions instead of thousands, hand-set vectors in the word and attention examples, and parameter estimates that ignore embeddings and architecture variants.
