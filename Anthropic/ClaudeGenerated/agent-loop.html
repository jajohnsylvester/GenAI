Inside the agent loop

An AI agent is a language model running in a loop. It reads the situation (perceive), decides on one next step (reason), uses a tool (act), and reads the result (observe). Then it goes around again until the job is done. Pick a task and watch one work.

    The four moves, in order

    Every agent, from a coding assistant to a travel planner, repeats the same cycle. The only thing that changes is which tools it has and what's in its context.

    STEP 1

    Perceive

    Gather the goal, the instructions, and every earlier result into the context window. This is all the model can see.

    system + goal + history
    STEP 2

    Reason

    The model reads the context and picks exactly one next action. Or it decides it has enough to answer.

    "Check the calendar before booking."
    STEP 3

    Act

    The model writes a tool call. The program around it runs the tool. The model never touches the outside world directly.

    calendar.check("2026-11-14")
    STEP 4

    Observe

    The tool's output, including any error, is appended to the context. Then the loop goes back to step 1 knowing more.

    → "Both days free."

    What an agent is made of

    Five parts. The model is only one of them.

    Model

    The language model. It reads text and writes text, including tool requests. On its own it can't browse, run code, or remember past sessions.

    Instructions

    The system prompt: the agent's role, its rules, and a description of each tool and when to use it.

    Tools

    Functions the agent may call, such as search, run code, read files, or send email. Each has a name, a description, and typed inputs.

    Context window

    The model's working memory for this task. Every step adds to it, and it has a size limit, so long tasks need summarizing or saved notes.

    Loop & stop rules

    Plain code that keeps the cycle going and decides when to stop: goal met, step limit reached, or a person needs to approve something.

    Chatbot versus agent

    A chatbot answers in one pass from what it already knows. An agent can go and find out, try things, check its work, and try again.

    When does it stop?

    A well-built agent always has a way out of the loop. These are the usual exits.

    Success

    The goal is met

    The model decides it has what it needs and writes a final answer instead of another tool call.

    Limit

    Step limit reached

    A hard cap, such as 20 steps, keeps a confused agent from looping forever.

    Hand-off

    A person must approve

    Risky actions like paying, deleting, or sending a message pause for a human yes.

    Budget

    Out of time or tokens

    The context window fills up or the cost budget runs out, so the agent reports what it has so far.

    The tasks above are scripted examples to show the mechanics. A real agent writes its own thinking and tool calls at each step, but the loop around it works exactly like this.
